# check-step

参数：节号（如 `2.3`）。没给的话，从当前分支名 `learn/<节>` 推断。

本机没有 GPU 时，所有命令都包进 `modal run scripts/modal_run.py --cmd "..."`；产物写到 `out/`，用文件头里的命令拉回本地。几个互不依赖的实验可以并行发到 Modal，省时间。

## 1. 重跑发现问题时的实验

- 用文档"发现问题"里（或者 `start-step` 时设计的）**同一个实验**，before 和 after 各跑一次。before 用这一节开始前的代码（`<名字>-main`，也就是 `learn/<节>` 的 merge base），可以用 `git worktree add` 开一个临时目录来跑，跑完删掉。
- 把两组数字并排给出来：现象消失了吗？
- **数字达标还不够**。要请学习者用一两句话解释：为什么这组数字说明问题被解决了。解释不出来，就回到分析环节重新讲。
- 机器上没有这一步要求的硬件时，明确说明哪些项目没法验收。

## 2. 带他读报告，数字对不上就看时间线

`bench.run` 的报告每一节都要读一遍，不是看一眼总吞吐就过：

1. 这一节的问题对应报告里的哪几个数？先让他指出来。
2. 有没有自相矛盾的数？比如 `cpu_launch ≈ gpu_forward` 而 `cpu_sample_wait ≈ 0`（CPU 发射是瓶颈，但 `gpu_busy` 却显示很高）；`wall max` 远大于 p99（有一次性的尖峰，通常是编译或懒初始化）。矛盾的数是最值得追的。
3. 追不下去就录时间线：`python -m bench.timeline --scenario <场景>`，把 `out/<场景>_{prefill,decode}.json` 拖进 https://ui.perfetto.dev。第一次看要带着走（1.1 文档"验收"一节有完整的导读路线）：认轨道，搜 `prefill step 1` 按 F 聚焦，W/S 缩放，看 CPU 那排的发射段和等待段谁长、GPU 那排的 kernel 之间有没有空隙、箭头是不是越来越斜。从 2.5 起换成 nsys（标准命令在 1.1 文档"看时间线"），`nsys stats --report nvtx_sum,cuda_gpu_kern_sum` 先出表，再决定要不要开图形界面。
4. 图上看到的和报告里的数字对起来：图负责看见，数字负责统计。

## 3. 回归

```bash
pytest tests/test_<节号，点换下划线>.py -x -q
pytest tests -x -q          # 前面各节的测试也要一起跑
```

失败时：给出失败的测试名和关键报错行，用提示的方式引导学习者自己定位（方向 → 位置 → 伪代码），不要直接改代码。

## 4. 代码质量

- 改动是否只服务于这一步的目标，有没有顺手改了无关代码。
- 命名、注释密度、关键字参数的写法是否和 nano-vllm 原有代码一致（`a=b`，不是 `a = b`）。
- 测量工具本身的开销（埋点、`perf_counter`、list append）要心里有数，后面做 CPU 开销的那一节会算这笔账。

## 5. 映射回顾

数字和测试都过了，再回头看代码：

```bash
git diff $(git merge-base HEAD <名字>-main) -- nanovllm/
```

对着文档"解决问题"开头的改动全景（或 `start-step` 时列的那张），一项一项在 diff 里找到对应的改动。然后请学习者用三五句话复述"这一节在代码层面做了什么"：加了什么结构、在哪些地方用上、什么东西挪了位置。说不全就指着改动全景里漏掉的那一项问他。这几句写进卡片，放在调用链之前（`compare-step` 收卡片时用）。

## 6. 输出

给一张小表：现象消失 ✅/❌（附 before/after 的数字）、学习者的解释 ✅/❌、回归测试 ✅/❌、映射回顾 ✅/❌。实测数字连同硬件一起补进文档的"验收"或卡片。

然后问学习者：**解决了这个问题之后，现在的瓶颈在哪里？** 用同一套观测工具再看一眼，用新浮现出来的问题引出路线图上的下一步（路线是固定的，不另开支线）。

全部通过后，建议下一步：

1. 用 `compare-step <节>` 和参考实现、DeepInfer 做对照，收卡片
2. commit，push 到学习者自己的 fork，提 PR：`learn/<节>` → 学习者 fork 的 `<名字>-main`；合并后在 `<名字>-main` 上打 `<节>-done` tag
3. 改 `LEARNERS.md` 里自己那一行的进度，PR 到上游 `main`（标题 `learners: <名字> at <节>`）
4. 做的过程中发现文档有错、实验设计有问题、数字对不上：开 issue 到上游，写清现象和原因
