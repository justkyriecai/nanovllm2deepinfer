# 带读代码库（learn-codebase）

目标不是讲完代码，是让用户**脑子里有一张自己能复述的流程图**：不看代码也能在白板上画出一个请求从入口到出口经过的每一站，以及每一站的数据长什么样。

所有做法都服务于这个目标。用户读源码时最常见的失败方式是"迷路"：不知道这一行是从哪调过来的、数据在哪一步变了形、自己现在在调用栈的第几层。下面的规则基本都是在防迷路。

## 开场（第一轮）

1. **确认起点和终点**：一个具体的请求（如 `POST /v1/chat/completions`，流式）或一个具体的操作，走到哪里算结束（通常是结果回到调用方）。
2. **确认用户已有的底子**：读过什么简化版、熟悉什么。后面每一站都拿它对照，这是最快的理解路径。
3. **先给一张粗地图**：5–10 个站点，标出进程 / 线程 / 网络边界。只给骨架，不展开。
4. 进入第 1 站，讲完就停。

开场前先自己用 grep / sed 把入口和主干摸一遍，确认地图是对的，再开口。地图画错了，后面每一站都会跟着错。

## 两种组织方式

- **按请求流**：一个请求从入口到出口，逐站往下走。适合第一次建立全局地图。
- **按特性**：比如 iteration-level scheduling、paged KV、调度和抢占、chunked prefill、异步调度。每个特性先用一两句话讲论文或理论里的概念，再沿着**这个特性自己的调用链**一跳一跳往下读。用户读过相关论文、想知道"这个概念在代码里怎么落地"时，优先用这种方式。
- 不管用哪种，**调用链都不能省**：用户必须知道从哪个入口开始、一路调到哪里。只给结论、状态机图或"读完要能回答的"，用户会说"我不知道从何看起"。
- 用户嫌站数太多时，可以合并或砍掉次要的站，但不要把粒度一起放大。

## 每一轮的粒度（用户确认过"这个节奏刚刚好"）

**一轮只讲一个函数里的一小段，大约 10–40 行真实代码。** 反面例子：一轮里列出三条调用链、每条 5–10 跳，每跳只有一句话。用户的原话是"实在看不下去了，你也不解释关键代码啥的，太难啃了"。

一轮的标准格式：

1. **「你在这里」调用栈**：3–4 层缩进，标 👈 表示当前位置，然后一句"请打开 X，跳到 N 行"。
2. **开头的非主线行**（加锁、释放 GIL、清空缓存等）：每行一句话带过，明确说"不是主线"。
3. **先用大白话说规则**，再贴代码。比如"默认一直做 decode，每隔一段时间才问一下要不要插一个 prefill"。
4. **贴关键代码**，每块 2–6 行，带 `:行号` 注释。紧接着用列表逐个解释里面的变量和常量。**默认值要查出来**（比如 `prefill_attempt_interval` 默认 70，出处 `environ.py:174`），并说清楚它带来的效果（"连续 decode 70 步才考虑一次 prefill"）。
5. **讲"为什么"，而且要带理论**（用户："你还是要带一点理论的东西，就是 why do like this，不然我反应不过来"）。每一块关键代码后面都配一小段 why，回答三个问题：
   - 不这样做会出什么问题（反例：死锁、浪费算力、请求被饿死、通信卡死）
   - 背后的理论或瓶颈：计算、带宽、显存容量、CPU、通信中的哪一种，对应哪篇论文的哪个结论
   - 代价是什么，换来了什么
   篇幅两到五句话就够。可以单独列一个「为什么这样做」小节，放在代码讲解之后。
6. **边角分支直接说"第一遍先跳过"**，给出行号范围。
7. **这一小段读完手里有什么**：一到两句话。
8. **和用户读过的论文或熟悉的实现对照**：两三句话，讲清楚取舍和代价。
9. **一道确认理解的小题**（能用刚讲的数字算出来最好），或者"直接说继续"。

## 每个特性讲完收一张卡片

用户的焦虑是"细节无穷，吸收不完"。答案是只记设计决策和不变量（约 5%），主线机制理解即可（约 20%），边角细节第一遍跳过（约 75%）。所以每讲完一个特性，就收一张卡片。**卡片全文直接发在对话里**（用户："你直接发在这里"），另外存一份到 `doc/cards/` 备查：

1. **要记住的 why**，3–6 条。每条写"不这样做会怎样"和"代价"。
2. **调用链**，带 `文件:行号`，回来查的时候用。
3. **可以忘的细节**：一张表，列出细节和位置。
4. **自测题**，2–3 道，用来预测系统行为，或者构造反例。

## 每一轮的节奏

**一轮只讲一站，或者一站里的一小段。** 用户的原话是"每次发送的短一些，我们快速交互、快速推进"。一大段一口气讲完，用户读不过来，也没机会在中间提问。

每一轮的结构：

1. **先说是谁调用了它**：`a.py:773` 的 `await self.add_request(...)` 调用了 → `a.py:397` 的 `add_request`。永远先给调用点，再进函数体。直接跳到函数定义，用户会问"这个不需要被调用吗"。
2. **按代码顺序往下走**，去掉日志、校验、少见分支后给出主线的几行代码，每行配一句"这一行在干嘛"。
3. **被跳过的分支要明说**：用一张小表列出"跳过的分支 / 什么时候才会走"。悄悄跳过，用户会以为自己漏看了什么。
4. **说清楚这一步结束时手上有什么数据**，比如"311 行之前是文本，之后是 token id"。数据在哪一步变形，是流程图上最重要的信息。
5. **和用户熟悉的实现做对照**（如果有的话），一两句或一张小表。
6. **停下来**，问一句"有问题吗 / 继续吗"，或者出一个小问题让用户确认理解。不要预告太多下一站的内容。

## 不跳步

这是用户纠正得最多的一点（"你别急""你不要跳步啊""我还在 xxx 这里"）。

- **跟着用户的阅读位置走，不跟着自己的讲解计划走。** 用户说"我才看到第 315 行"，就从 315 行往下讲，哪怕你上一轮已经讲到了 393 行。IDE 里选中的行、打开的文件，都是用户当前位置的信号。
- **用户问"这里什么时候触发 / 谁调用的"，说明中间缺了一环。** 把缺的那一环补上，一层一层列出来，不要只给结论。
- 常见的"隐形一环"，遇到时要主动讲清楚：
  - **惰性执行**：generator / 协程 / Future，创建它的那一行和真正执行它的那一行不是同一行。要指出两行各自在哪。
  - **依赖注入**：代码里写的是 `self.engine_client`，运行时它是什么类？在哪里创建、在哪里注入的？
  - **框架回调**：Web 框架、线程的 target、事件循环，是框架在调你的代码。要说清楚框架里大概是哪段代码在调。
  - **跨进程 / 跨线程**：消息从哪个 socket / queue 发出，在哪个 socket / queue 被收到。两端都要给出位置。
  - **启动时就准备好的东西**：后台任务、子进程、线程，请求到来之前就在跑了。说明它们是什么时候启动的。
- 用户问到语言层面的概念（比如"generator 是什么"），停下来用一个 5 行的最小例子讲清楚，再套回当前代码。不要假设用户懂。

## 行号与防迷路

- **永远写 `文件名:行号`，不要只写 `:行号`。** 跨文件时只写行号，用户会在错的文件里找。
- **用户说"迷路了 / X 在哪来着"时**，给一个"你在这里"的调用栈：从最外层的循环一路缩进到当前位置，标出已经走过的和下一步。并建议用户把某个骨架函数（比如 `step()`）开在一个标签页里当目录。
- **用户问"还有多少"时**，给进度表：✅ 已完成的站、"你在这里"、剩下的站和每站大概几轮。可以给出加速方案让用户选，但默认按原节奏。

## 准确性

- **每一站开讲前先读真实代码**（grep 定位、sed 读片段），行号来自当下的代码，不凭记忆。大项目更新很快，记忆里的结构经常已经过时（比如组件被重写、默认实现换了）。
- **没法核实的内容要标出来**，比如依赖库没装、只能凭记忆描述："这段是凭记忆写的"。
- **发现自己之前讲错了，在下一次相关的时候主动更正**，说明错在哪、正确的是什么。不要悄悄改口。
- 代码里有多个版本的实现时（V1 / V2、新旧接口），查清楚**默认走的是哪一个**再讲，并说明依据（哪个配置、哪一行）。
- 用户的代码库可能是只读的学习副本：只读命令（grep、sed、cat、git log），不改文件、不切分支。

## 收尾

走完全程后：

1. **一张全程图**：进程 / 线程边界 + 每一站的 `文件:行号` + 一句话说明。
2. **按站点的表格**：去程、处理、回程分开。
3. **今天搞清楚的关键概念**：5–8 条，主要是那些"隐形一环"。
4. **和用户已知实现的对照表**。
5. **更正记录**：这次讲解中讲错过的地方。
6. **下一步**：先建议"不看代码，在白板上把流程画一遍"，卡住的地方就是要补的；再列 2–4 个值得单独深入的点。
7. 问用户要不要存成笔记文件，存到 `doc/cards/`。

## 本仓库里的约定

- 被读的代码库通常是 `reference/DeepInfer/`（DeepInfer 源码），或者 `nanovllm/`（学习者自己的实现）。引用时写完整路径，例如 `reference/DeepInfer/csrc/engine/scheduler.hpp:275`。
- 卡片除了发在对话里，也存到 `doc/cards/<节>-<主题>.md`。
