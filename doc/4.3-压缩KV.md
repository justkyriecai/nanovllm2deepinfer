# 4.3：两个 token 压成一个 latent，chunk 边界切在中间

> 起点：4.2 做完的代码　硬件：1×B200　预计改动：500–800 行　轴：2 显存 / 4 模型结构

## 1. 发现问题

**关注什么**：压缩层（`compress_ratios[l] == 1 / 2`）的主 KV。压缩比 1 的层每个 token 一个 latent，和 3.1 的 MLA 一样；压缩比 2 的层**每两个 token 出一个 latent**，上下文越长省得越多。

先按"显然"的方式实现压缩比 2：prefill 时把相邻两个 token 的投影做一次加权合并（权重由一个 gate 决定），存一个 latent；decode 时每两步存一次。在 harness 里对拍三种情况：

```bash
python -m tests.v4.harness --layer <ratio2 层> --prompt-len 4096 --compare attn                 # 单 chunk
python -m tests.v4.harness --layer <ratio2 层> --prompt-len 4097 --chunk 1024 --compare attn    # 奇数长度 + chunked prefill
python -m tests.v4.harness --layer <ratio2 层> --decode --nextn 5 --reject-at 2 --compare attn  # 投机解码部分拒绝
```

**先预测**：chunk 长度 1024 时，第 1024 个 token 和第 1025 个 token 要合成一个 latent，它们在不同的 forward 里，怎么合？投机解码验证了 6 个位置、只接受前 2 个，第 3 个位置的"半个 latent"状态要退回到什么？

**现象**：

- 单 chunk 对得上。
- 跨 chunk 对不上：边界处那个 latent 用了错误的配对。朴素实现没有地方存"上一个 chunk 最后一个 token 的投影"。
- 投机解码对不上：第 3 个位置的 draft 和第 2 个位置的接受 token 被合成了一个 latent 存进去了，下一步重算第 3 个位置时，第 2 个位置的"半个状态"已经被污染。
- 另外，这一层的 cache 每 token 288 B（FP4）或 528 B（FP8），3.1 的 bf16 latent 是 1152 B；FP4 的 scale 是每 16 个元素一个 e4m3，和 3.3 的 FP8 per-32 UE8M0 不是一套。

## 2. 分析问题

- **追问链**：边界和回退都错 → 压缩是一个**跨 token 的归约**（窗口为 2 的门控累加），归约的中间状态必须跨 forward 保留 → 每序列一个小的 fp32 状态环（4.1 的 `ca_state`）→ 状态环也要能回退 → 环长 `ratio + max_backtracking − 1` → 每个 forward 的输出是"本次新凑满的 latent"，位置和 slot 由 C++ 按 `pos / ratio` 算 → 存之前还要 norm、RoPE（压缩层有自己的 `compress_rope_theta`）、量化到 FP8 / FP4、按 slot 散到 paged cache，这几步融合成一个 kernel。
- **本质**：压缩比 2 把 KV 容量再减半，代价是引入了一个**有状态的算子**。有状态就意味着：chunk 边界、投机解码回退、抢占重算、fork，每一条路径都要带着状态走。DeepInfer 把状态放在固定槽位里（和 SWA 环同一块 `StateBlock`），而不是放在 paged block 里，就是为了让这些路径只多拷一个固定大小的东西。
- **量化**：V4.1 的压缩维 512（`kv_lora_rank + rope`，`V41_FORMAT.quantized_elements`）。FP8：512 B + 16 B scale = 528 B/latent；FP4：256 B + 32 B scale = 288 B/latent；压缩比 2 再除以 2。一个 128k 上下文、ratio 2 的层：`65536 × 288 B ≈ 19 MB`，对比 3.1 的 bf16 MLA `131072 × 1152 B ≈ 151 MB`。
- **理论**：`reference/gpu-perf-engineering-resources/` §4 KV cache systems：DeepSeek-V2（latent）、KIVI（KV 量化，key 和 value 分开处理）、QuaRot（旋转去 outlier 再量化，DeepInfer 的存 kernel 名字里的 `hadamard` 就是这个思路的可选步骤）；§2 "Tensor cores and low precision"：OCP MX 规范（FP4 的 E2M1 + 共享 scale）。
- **DeepInfer 怎么做**（`models/v4_modules/compress.py`）：
  - **投影**：`SoftmaxAPEGatedColumnParallelLora`（`mla_attn.py:63`）：`A` 出 latent，`Gate` 出 score；压缩比 1 时 softmax 恒为 1 所以没有 `Gate`（bf16 输出）；压缩比 2 时两者都有，输出 fp32 `[score | latent]`（`:82-100`）。这两个投影**不走 FP8**（注释写明"不参与 fp8 量化"），精度敏感。
  - **压缩**：`Compressor.forward_pre_norm`（`compress.py:82`）：ratio 1 直接返回；ratio 2 调 `compress_and_update_state_prefill`（`tilelang_ops/compress.py:20`）或 `_decode`（`:74`）：输入 `score / latent [total_q, dim] fp32`、`state_cache [num_state_slots, ring, 2, dim] fp32`、`state_block_idx`、`cu_seqlens_q / k`、`cu_compressed_seqlens_q`，输出 `kv_compressed [total_compressed, dim] bf16`。kernel 内按位置做 score 的 softmax 加权累加，窗口没凑满的部分留在状态环里；`[ring, 2, dim]` 的 2 是 score 和 latent 各一份。
  - **状态环长**：`get_inference_compress_block_size`（`cache_engine.py:131`）`= ratio + max(0, max_backtracking − 1)`，decode 时 `max_seqlen_q = nextn + 1`（`compress.py:117`）。回退不需要撤销：下一步按位置重新累加，覆盖掉脏的槽。
  - **哪些 token 产生 latent**：`update_common_v4`（`prepare_tensor_input_v4.cpp:26`）：prefill 时每序列产生 `seqlen_k / n − (seqlen_k − seqlen_q) / n` 个，至少 pad 1 个（`:50-66`）；decode 时只有 `(orig_pos + 1) % n == 0` 的 query 产生（`:78-88`），其余 slot 填 -1。`positions_c = j × n`，slot 按 `compressed_block_size = block_size / n` 换算。
  - **存**：`forward_store_kv_cache`（`compress.py:131`）：`fused_norm_rope_hadamard_cast_store_kvcache` 一个 kernel做 norm（`kv_lora_norm_out_scale`）、RoPE（`compress_rope_theta`，只转最后 64 维）、cast（`CastArgs.from_cache_format`，FP8 或 FP4）、按 `slot_mapping_store_ca[ratio]` 散到 `ca_cache`；`out_stage="norm"` 时顺便把 norm 后、RoPE 前的 KV 拷一份出来给 indexer（4.4）。
  - **读**：prefill `load_paged_kv_cache`（`attn.py:830-836`）把 paged 的 FP8 / FP4 解压成 bf16 `[total_k_compressed, 1, 512]` 放到 4.2 的拼接 buffer 尾部；decode 直接让 FlashMLA 读 FP8 cache（`is_fp8_kvcache=True`），SWA 环作 `key_cache`、压缩 cache 作 `key_cache_extra`，各带自己的索引（`attn.py:645-652`）。非稀疏的压缩层索引来自 `input_metadata.kv_ca_index[ratio]`（`:580`，就是 `0..n_compressed−1`），稀疏层来自 4.4。
  - **格式**：`KVCacheFormat`（4.1），`token_interleaved=True` 表示每 token `[data | scale]` 相邻。

## 3. 要做什么

### 3.1 投影

**改哪里**：`nanovllm/models/deepseek_v4.py`。

- `PackedWkv`：`A [H → 512]`，ratio 2 时还有 `Gate [H → 512]`，输出 fp32 `[score | latent]`；bf16 权重，不量化。
- 压缩层的 RoPE 用 `compress_rope_theta`，和 SWA 层的 `rope_theta` 不同；yarn 参数照 3.1。

### 3.2 压缩 kernel 和状态环

**新建** `nanovllm/layers/compress.py`（Triton）。

- `ca_state [num_state_slots, ring, 2, 512] fp32`，`ring = ratio + max_backtracking − 1`（4.1 的 `StateBlock` 已经留了位置）。
- 先写 PyTorch 参考实现（照 `tilelang_ops/compress.py:146` 的 `_ref` 的语义：逐序列逐位置，softmax 加权累加，凑满 `ratio` 个输出一个），再写 Triton。prefill 和 decode 两个入口。
- C++ 算 `positions_c[ratio]`、`slot_mapping_store_ca[ratio]`、`cu_compressed_seqlens_q`、`compressed_batch_mapping`；decode 时不产生 latent 的 query 行 slot = -1。

### 3.3 存和读

- 存：norm → RoPE → cast → scatter，先用 Triton 分开写，返回 pre-rope 的 KV 供 4.4 用；4.11 融合。
- FP4 cast：e2m1 + 每 16 个一个 e4m3 scale（`V41_FP4_FORMAT`），和 3.3 的 FP8 cast 并列实现；`use_fp4_sparse_kv` 配置决定主 KV 用哪种。
- 读：`load_paged_kv_cache` 的 Triton 版（按 `load_segments` 把 paged 的 FP8 / FP4 解压到连续 bf16 buffer）；decode 把 `ca_cache` 作为 `key_cache_extra` 传给 FlashMLA。

### 3.4 状态的生命周期

- 抢占重算：状态环随槽位释放，重算时从头累加（2.3 的 `reset_for_recompute` 要清 `state_id`）。
- fork（2.4）：子序列拷贝父序列的 `StateBlock`（SWA 环 + 压缩状态）。
- ZOS（2.7）：decode 时哪些 query 产生 latent取决于接受了几个 draft，CPU 不知道；先按"全部接受"准备上界的 slot，GPU 上按 `last_valid_offset` 把超出的置 -1（和 2.8 的 `compute_seqlens_k_zos` 一个思路）。

## 4. 验收

同一个实验重跑：

1. 三种情况（单 chunk、奇数长度跨 chunk、投机解码部分拒绝）harness 上 attention 输出和 DeepInfer 一致。
2. 显存：ratio 2 层的 cache 每 token 字节数按格式减半，报告里给 128k 上下文下 bf16 MLA / FP8 / FP4 三种的数字。
3. `tests/test_4_3.py`：(a) 压缩 kernel 和 PyTorch 参考一致，含 chunk 边界、`cu_compressed_seqlens_q` 为 0 需要 pad 的序列、decode 下 `seqlen_q = 6` 部分有效；(b) 状态环在"写 6 个、退回 2 个、再写 6 个"之后和"顺序写"一致；(c) FP4 / FP8 cast 和反量化的误差在格式理论范围内；(d) `load_paged_kv_cache` 和参考一致；(e) 前面全过。

**新浮现的问题**：压缩层的 decode attention 还是要读完整个上下文的 latent，128k 下每层 attention 时间随长度线性涨。V4.1 的压缩层都带稀疏 indexer，只读 top-k。这是 4.4。

## 常见坑

- `compressed_block_size = block_size / ratio`，slot 换算用它，不是 `block_size`；一个 block 在 ratio 2 的层只装 64 个 latent。
- decode 下 `seqlen_q = 6` 时只有 `(pos + 1) % 2 == 0` 的位置写 cache，其余行 slot 必须是 -1，kernel 要跳过。
- 状态环的 score 和 latent 要同时存（`[ring, 2, dim]`），只存累加结果没法在回退后重新归一化。
- `kv_lora_norm_out_scale`、`use_kv_norm_weight`：V4.1 的 norm 有输出缩放，权重可能不存在，按 config 处理。
- 投影是 fp32 输出，压缩 kernel 在 fp32 做，存之前才降精度；在 bf16 做累加会和 DeepInfer 对不上。
