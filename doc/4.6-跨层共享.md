# 4.6：二十层 consumer 各存一份一样的 KV

> 起点：4.5 做完的代码　硬件：1×B200　预计改动：300–500 行　轴：2 显存

## 1. 发现问题

**关注什么**：4.5 之后所有 consumer 层的 KV 都是 `shared_hidden` 的投影。看 config：`kv_source_layer_ids`、`index_source_layer_ids`、`index_k_source_layer_ids`、`candidate_source_layer_id`。

```bash
python - <<'EOF'
import json; c = json.load(open("config.json"))["text_config"]
print(c["kv_source_layer_ids"], c["index_source_layer_ids"], c.get("index_k_source_layer_ids"), c["candidate_source_layer_id"])
EOF
python -m tests.v4.harness --layers 0..K --report kv-bytes-per-token
```

**先预测**：如果 `kv_source_layer_ids` 只有几个值，那其它压缩层的 `PackedWkv` 权重是什么？它们的 cache 里存的是什么？

**现象**：

- HF checkpoint 里不在 `kv_source_layer_ids` 的压缩层**没有** `PackedWkv` 权重；不在 `index_source_layer_ids` 的层没有 indexer 权重。4.1 的 cache 布局给每个压缩层都分了 `ca_cache` 和 `ica_cache`，这些层的 cache 从来没被写过，attention 读的是垃圾（harness 对拍从这些层开始错）。
- 每 token 的 KV 字节数按层数线性涨，但按 config 真正需要存的只有 source 层那几份。

## 2. 分析问题

- **追问链**：consumer 层的 KV 全是 `shared_hidden` 的函数 → 如果投影权重也相同，KV 就逐位相同 → config 用 source 层 id 表达"这一层用那一层的 KV" → 三张映射分别管主 KV、index-K、top-k 索引 → 它们的粒度有包含关系：top-k 是用 index-K 算的，index-K 是用主 KV 的 pre-rope 投影算的，所以 `topk ⊆ index-K ⊆ KV` 的分段必须嵌套 → 共享不能跨 YoCo 边界（producer 的 KV 来自本层 hidden，consumer 的来自 shared hidden）→ cache 层面：consumer 层的 `ca_cache / ica_cache` 直接**别名**到 source 层的张量，零额外显存；forward 层面：source 层写、consumer 层读，中间要有一个跨层传值的对象。
- **本质**：跨层共享把 KV 容量从"层数 × 每 token"变成"source 层数 × 每 token"。它和 4.5 是一对：YoCo 让共享成为可能，共享拓扑让它落到显存上。
- **量化**：按 config 数 source 层的个数。假设 20 个 consumer 层只有 `s` 个 kv source，consumer 段的 KV 容量就是原来的 `s/20`。
- **理论**：Cross-Layer Attention（Brandon et al. 2024，不在清单里）：相邻层共享 KV；`reference/gpu-perf-engineering-resources/` §4 KV cache systems 的 GQA 是同一思路在头维度上的版本。
- **DeepInfer 怎么做**（`models/v4_modules/cross_layer.py`）：
  - **拓扑** `SharedLayerTopology`（`:22`）：从 config 的 `layer_info_shared_cfg`（`config.py:68` 把 source id 列表转成 `{layer: source}`）建三张覆盖所有层的映射 `layer_kv_map / layer_index_k_map / layer_index_module_map`（`:77`），不参与的层 `map[l] = l`。构造时一次性校验（`:89`）：分段连续（consumer 指向前面最近的 source，`:169`）；`topk ⊆ index-K ⊆ KV` 的细化关系（`:182 / :191`）；不跨 YoCo 边界（`:116`）；consumer 层必须带共享配置，否则 cache engine 会给它分独立 cache 而没人写（`:105-112`）。候选块的 source 另有一张稀疏映射（`:158`）。
  - **cache 别名**：`KVCacheManager.process`：`index_mapped_layer_id != layer_id` 时 `ica_cache = cache_list[src].ica_cache`（`cache_engine.py:431`），`kv_mapped_layer_id != layer_id` 时 `ca_cache = cache_list[src].ca_cache`（`:449`），不推进 `kv_offset`。
  - **模块**：consumer 层没有 `PackedWkv` / `index_attn`（`mla_attn.py:247-259`，builder 按拓扑决定谁持有），index-K consumer 直接复用 source 的 `k_proj / k_norm`（`builder.py:80-91`）。
  - **跨层传值** `CrossLayerRuntime`（`cross_layer.py:277`）：每个 forward 新建一个，逐层传同一引用：`shared_hidden`（4.5）、`pre_rope_kv`（kv source 写、index-K source 读）、`topk_indices`（index source 写、index consumer 读）、`loaded_prefill_kv`（kv source 解压一次，consumer 复用，只覆盖 SWA 段，`attn.py:723-750`）、`loaded_prefill_index_kv`、`block_candidate_idxs` 和候选块的调度缓存。每个值只有一个槽：拓扑是分段的、层按序执行，consumer 要的永远是前面最近的 source 写的那个。
  - **attention 里的分支**：`is_kv_source / is_index_source / is_index_k_source`（`attn.py:256-264`）：`_compute_kv_ca_index`（`:525`）里 source 存、consumer 从 runtime 取；consumer 不调 `_store_main_kv`（`:583`）。

## 3. 要做什么

### 3.1 拓扑

**新建** `nanovllm/models/cross_layer.py`。

- `SharedLayerTopology`：三张映射 + 候选块映射；照 DeepInfer 的校验规则写断言（分段、细化链、不跨 YoCo 边界、consumer 必须带配置）。
- 4.1 的 `KVCacheManager.process` 接拓扑：consumer 层的 `ca_cache / ica_cache` 别名 source 层的，`kv_length = 0`。
- 层构造按拓扑决定持有哪些模块；index-K consumer 复用 source 的 `k_proj`。

### 3.2 跨层 runtime

- `CrossLayerRuntime` dataclass：把 4.4 的候选块 dict 和 4.5 的 `shared_hidden` 收进来，加 `pre_rope_kv`、`topk_indices`、`loaded_prefill_kv`、`loaded_prefill_index_kv`。
- 模型 forward 每步新建一个，逐层传。

### 3.3 attention 分支

- kv source：存主 KV，把 pre-rope KV 放进 runtime；index-K source：用 runtime 的 pre-rope KV 投影 index-K；index source：算 top-k 放进 runtime；consumer：只读。
- prefill：kv source 把解压后的 KV buffer 放进 runtime，consumer 复用，只重写 SWA 段。
- 4.5 的 `_store_yoco_full_kv` 同样按 source 分支。

## 4. 验收

1. 同一个实验重跑：每 token KV 字节数按 source 层数算，报告里给前后对比；harness 上所有层对拍通过（之前读垃圾的 consumer 层现在对上了）。
2. 显存：`get_kvcache_layout` 对 consumer 层返回 `kv_length = 0`，和 DeepInfer 的输出逐字节一致（4.1 的测试重跑）。
3. `tests/test_4_6.py`：(a) 拓扑校验：每一条非法 config（跨段、细化链断、跨 YoCo 边界、consumer 缺配置）都在构造时报错；(b) cache 别名：写 source 层的 cache，consumer 层读到同样的字节；(c) `loaded_prefill_kv` 复用时 SWA 段被正确覆盖、主 KV 段不变；(d) 前面全过。

**新浮现的问题**：attention 和 MoE 都对上了，整层对拍还差残差流：V4.1 的残差不是一条，是 `hc_mult = 4` 条，每个子层前后都要混合。这是 4.7。

## 常见坑

- 别名张量的 `stride(0)` 是整块的，和 4.1 一样；别名之后不要再 `as_strided` 一次。
- `topk ⊆ index-K ⊆ KV` 是段的嵌套，不是"同一层"：一个 kv source 可以服务多个 index-K source，反过来不行。
- consumer 层在 prefill 复用 `loaded_prefill_kv` 时只能改 SWA 段，主 KV 段一改后面的 consumer 就错了。
- 跨层 runtime 的值每步新建，不要跨步持有（4.5 的 `shared_hidden` 在 decode 时每步重新捕获）。
- `candidate_source` 的映射是稀疏 dict，不参与的层不出现，也不会切断共享段（`cross_layer.py:158-166`）。
