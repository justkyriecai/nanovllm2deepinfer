## 发现问题

**关注什么**：前面 34 节都是分块对拍：第 4 章对单层，第 5 章用 V2-Lite 对机制。没有一个端到端的数字说明整个引擎和 DeepInfer 等价。DeepInfer 自己的"端到端正确"定义只有一个：`tests/models/test_offline_inference.py` 跑 `examples/offline_inference.py`，每个 DP rank 的每个样本的 `decode_ppl` 和 `tests/models/offline_decode_ppl.json` **逐样本精确相等**（`test_offline_inference.py:154-158`，`actual == expected`，不是近似）。

先把 DeepInfer 本身跑一遍，拿到基准：

```bash
cd reference/DeepInfer
python examples/offline_inference.py --ep 8                       # 8×B200，EP 8，DP 8
python examples/offline_inference.py --ep 8 --cp 2                # DP 4 × CP 2
python examples/offline_inference.py --ep 8 --long_context        # 16389 in / 4096 out，nextn 5
python examples/benchmark.py --decode_num_requests 64 --context_length 32768 --enable_eplb
```

**先预测**：我们的引擎在同样配置下，哪些地方可能和 DeepInfer 差出 bf16 容差之外？列一张清单（投机解码的接受率、EPLB 的重排时机、batch-invariant 的开关、采样的 seed、FP4 的取整……）。

**现象**：装配之后第一次跑，PPL 对不上是正常的。差异要能定位到节。这一节的内容就是**定位和修**。

## 分析问题

- **追问链**：PPL 对不上 → 先退到贪心（`temperature = 0`）排除采样 → 关投机解码排除 2.8–2.10、4.10 → 关 EPLB 排除 5.4 → `cp = 1` 排除 5.5 → `dp = ep = 1`（如果一张卡放得下前几层）排除 5.1–5.3 → 剩下的是模型本身：用第 4 章的 harness 逐层找第一个不一致的层 → 修 → 一层层把开关加回来，每加一个都要对上。
- **本质**：期末考试考的不是新机制，是**所有机制同时打开时的一致性**。DeepInfer 把一致性做成了可执行的东西：`DEEPINFER_BATCH_INVARIANT=1`（测试默认开，`test_offline_inference.py:110`）+ 固定 seed + 逐样本精确相等。我们要达到同样的标准，就得把 2.12 的 batch-invariant 贯穿到第 4、5 章的每一个 kernel。
- **量化**：短 PPL 测试 rank r 有 `5 × (r + 1)` 个样本（rank 0 五个、rank 1 十个，`test_offline_inference.py:134`，黄金文件里也是这样）；长 PPL 测试 16389 in / 4096 out，nextn = 5，单次 30 分钟超时（`:126`）。
- **理论**：没有新理论。`reference/gpu-perf-engineering-resources/` §3 "Profiling, benchmarking, and correctness" 的方法论；§5 "Serving benchmarks" 的指标定义，用来写最后的吞吐报告。
- **DeepInfer 怎么做**：
  - **配置**：`examples/offline_inference.py`：`--ep 8`，`dp = ep / cp`，`max_num_batched_tokens = 32768`、`max_model_len = 32768`、`max_num_seqs = 4`、`gpu_memory_utilization = 0.85`、`lookahead_tokens = 1`、`sampler_force_topk = 4096`，EPLB 开（`DEEPINFER_OVERRIDE_NUM_EXTRA_EXPERTS = 32`、`DEEPINFER_EXPERT_REARRANGEMENT_STEP_INTERVAL = 30`、`DEEPINFER_REARRANGE_AFTER_PREFILL_IN_NORMAL_ENGINE = 1`，`examples/_config.py:66-83`），`DEEPINFER_USE_NEXTN_DECODE = 5`，NVIDIA 上 `DEEPINFER_BATCH_INVARIANT = 1`。
  - **样本**：`_prompts.py:65` 按 `dp_rank` 准备样本（两条纯文本、一条单图、一条三图、一条五图，`examples/README.md`），长测试把 prompt 补到 16389 token（`:120`）。
  - **输出格式**：`print_output`（`offline_inference.py:67-93`）每样本一行 `DP {rank}; INPUT …; OUTPUT …; output_tokens=; accept_rate=; decode_ppl=`，`decode_ppl = exp(−mean(logprobs))`，测试用正则解析（`test_offline_inference.py:49-60`）。
  - **黄金文件**：`offline_decode_ppl.json` 按 `platform / workload / rank` 存；`refresh_offline_decode_ppl.py` 在确认数值变化合理后更新；多节点按 rank 分片、文件锁（README）。
  - **结构化输出**：`--check_structured_output` 在同一个 LLM 上再跑 regex / JSON / EBNF 三种约束并检查正常 EOS（2.11）。
  - **吞吐**：`examples/benchmark.py`：prefill 和 decode 两段解耦（`--prefill_batch_size`、`--non_cached_tokens`、`--decode_num_requests`、`--context_length`），README "Benchmark" 一节解释了 `N` 和 `K` 的关系。
  - **多模态**：五个样本里三个带图，走 `MultimodalEmbedding` 和 vision encoder（`containers.py:40-58`）。这是本路线**没有覆盖**的部分：按 README 的说法它是 EPD 分离里独立的一段。两种选择：(a) 把 DeepInfer 的 vision encoder 和 aligner 整体当 vendor 模块接进来；(b) 黄金文件只对两条纯文本样本。先做 (b)，(a) 可选。

**思考题**：短 PPL 测试里 rank r 有 `5 × (r + 1)` 个样本，各 rank 的样本数故意不同。这和 5.3 的投票、5.4 的 EPLB 有什么关系？如果每个 rank 都是 5 个样本，哪类 bug 会漏过去？

## 解决问题

### 任务 A：装配（约 2 小时，你写约 150 行）

- **目标**：`nanovllm/models/deepseek_v4.py` 装全 40 层 + DFlash；8×B200 下 `dp = ep = 8` 和 `--cp 2` 两种配置都能跑完短 PPL 并打出和 DeepInfer 同格式的每样本一行；`tests/golden/v41_flash_ppl.json` 照 `offline_decode_ppl.json` 的结构。
- **思路**：对回"所有机制同时打开"。第 4 章只装前 `K` 层，现在装全；第 5 章的机制全开：DeepEP（B200 上 MoE 走 4.9 的 Mega MoE，`use_mega_moe` 的条件是 EP 组在 NVLink 域内）、投票、EPLB（32 个冗余专家，30 步重排，prefill 后重排）、CP。样本准备和输出格式复现 DeepInfer 的：按 `dp_rank` 准备、每样本一行 `DP {rank}; … decode_ppl=`，`decode_ppl = exp(−mean(logprobs))`，这样黄金文件可以用同一个正则解析。

### 任务 B：定位工具（约 40 分钟，你写约 80 行）

- **目标**：`python -m bench.bisect` 按固定顺序逐个切换一组开关，每个配置跑一遍短 PPL，打出第一个对不上的开关；对不上时能接上第 4 章的 harness 逐层比第一个 decode 步的 hidden。
- **思路**：对回追问链"从外到内一层层排除"。开关：`temperature`、`nextn`、`eplb`、`cp`、`batch_invariant`、`yoco_mode`、`use_mega_moe`、`fp4_sparse_kv`，顺序就是追问链的顺序（采样 → 投机 → EPLB → CP → …）。一次只切一个，两个一起切对不上就不知道是谁。第一个对不上的开关指向哪一节，就回那一节的 harness 去找第一个不一致的层。
- **已备好**：`bench/bisect.py` 的 CLI、开关到 `Config` 的映射、每个配置起子进程跑短 PPL 和解析结果的框架；`tests/test_5_7.py` 里 `bisect` 的冒烟。

### 任务 C：一致性贯穿（约 1 小时，你写约 100 行）

- **目标**：2.12 的 `batch_invariant` 开关在第 4、5 章的每个 kernel 上都有效；采样的 RNG 和 DeepInfer 用同样的 seed 和 tag 常量；同一配置连跑 3 次 PPL 完全一致。

## 验收

1. **短 PPL**：`--ep 8` 和 `--ep 8 --cp 2` 两种配置下，纯文本样本的 `decode_ppl` 和 DeepInfer 在同一台机器上跑出的数字**逐样本相等**（按 DeepInfer 的标准）；带图样本按分析问题里多模态那一条的选择 (a) 或 (b)。
2. **长 PPL**：16389 in / 4096 out、nextn 5，同样逐样本相等；接受率和 DeepInfer 的 `accept_rate` 在同一水平。
3. **结构化输出**：regex / JSON / EBNF 三种约束全部符合并正常 EOS。
4. **吞吐**：`benchmark.py` 同配置下 decode 吞吐不低于 DeepInfer 的 90%，prefill 不低于 90%；报告里给分解（attention / MoE / 通信 / 采样）。
5. **稳定性**：同一配置连跑 3 次 PPL 完全一致（batch-invariant）。
6. `tests/test_5_7.py`：就是 PPL 测试本身（照 `test_offline_inference.py` 的结构，子进程跑、正则解析、逐样本比），加 `bisect` 的冒烟。
7. **报告** `doc/report/5.7.md`：三张表。(1) 短 / 长 PPL 逐样本（ours vs golden），(2) 吞吐（`benchmark.py` 同配置：prefill tok/s、decode tok/s、TTFT、TBT、MFU，和 DeepInfer 并排），(3) 从 nano-vllm 到这里每一节的 before / after 数字汇总（1.1 开始的所有报告）。

## 常见坑

- 黄金文件是 DeepInfer **在你这台机器上**跑出来的数字，不是仓库里的（仓库里的对应它的 CI 机器和 vendor 版本）；先用 `refresh_offline_decode_ppl.py --output` 生成本机基准。
- 精确相等的前提是 batch-invariant + 固定 seed + 同样的 `sampler_force_topk`；少一个就只能近似相等，那就不是 DeepInfer 的标准。
- 投机解码下 `decode_ppl` 用的是被接受 token 的 logprob（`output[i].token_logprobs`），draft 的接受与否不改变分布，但 `accept_rate` 受 2.9 / 4.10 的置信度影响。
- EPLB 的重排时机影响归约顺序，`allow_multiple_reduction=False` 是精确相等的条件之一。
- 一次只开一个开关去找差异，两个一起开对不上就不知道是谁。
- 长 PPL 单次 30 分钟，8×B200 一小时几十美元；先在短 PPL 上对齐，长 PPL 最后跑一次。
